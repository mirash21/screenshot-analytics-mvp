# Исправление ложных срабатываний VK и других приложений

## Проблема

Система ложно определяла VK и другие непродуктивные приложения в рабочих текстах из-за слишком общих ключевых слов:

- **"контакт"** - встречался в рабочих документах, CRM, email
- **"стена"** - могла быть в новостях, статьях
- **"закладки"** - есть в браузерах, 1С, документах
- **"видео", "музыка"** - общий рабочий контекст
- **"корзина", "магазин", "купить", "скидка"** - рабочие закупки

## Решение

### 1. Убраны общие ключевые слова

**До:**
```python
'vk': ['vk.com', 'vk', 'вконтакте', 'контакт', 'стена', 'закладки'],
'youtube': ['youtube.com', 'youtube', 'youtu.be', 'видео', 'музыка'],
'shopping': ['aliexpress', 'alibaba', 'amazon', 'магазин', 'купить', 'скидка']
```

**После:**
```python
'vk': ['vk.com', 'vk.com/', 'vkontakte.ru', 'вконтакте.ру'],
'youtube': ['youtube.com', 'youtube', 'youtu.be'],
'shopping': ['aliexpress', 'alibaba', 'amazon']
```

### 2. Улучшена проверка коротких слов

Метод `_keyword_in_text()` теперь использует более строгие границы для очень коротких слов (1-2 символа):

```python
def _keyword_in_text(self, keyword: str, text_lower: str) -> bool:
    """Поиск ключевого слова с границами для коротких токенов"""
    kw = keyword.lower()
    # Для очень коротких слов (1-2 символа) требуем строгие границы
    if len(kw) <= 2:
        return bool(re.search(rf'(?<![\w.]){re.escape(kw)}(?![\w.])', text_lower, re.IGNORECASE))
    # Для слов до 3 символов - границы слов
    if len(kw) <= 3:
        return bool(re.search(rf'\b{re.escape(kw)}\b', text_lower, re.IGNORECASE))
    # Для длинных слов - простое вхождение
    return kw in text_lower
```

## Результаты тестирования

✅ **Все тесты пройдены:**
- "Контакт с клиентом установлен" → VK НЕ определяется
- "Стена новостей компании" → VK НЕ определяется  
- "Закладки в браузере Chrome" → VK НЕ определяется

## Рекомендации

Если в будущем нужно добавить больше ключевых слов для определения приложений:
1. Используйте только специфичные URL/домены (vk.com, youtube.com)
2. Избегайте общих существительных (видео, музыка, магазин)
3. Для рабочих приложений используйте только названия программ (vscode, jira, slack)
4. Не добавляйте общие рабочие термины (код, терминал, презентация, письмо)
5. Тестируйте на рабочих текстах чтобы избежать ложных срабатываний
