## Модули системы

### 1. Data Collector (Модуль сбора данных)

**Ответственность:** Автоматический сбор и организация скриншотов

**Технологии:**
- Python 3.11
- Pillow (для валидации изображений)
- SQLite3

**Основные компоненты:**
- `collector.py` - Главный цикл сканирования
- `file_parser.py` - Парсинг структуры папок
- `database.py` - ORM для работы с БД
- `config.py` - Конфигурация путей

**Алгоритм работы:**
```
1. Сканирование входящей папки (каждые 5 мин)
2. Поиск файлов изображений (.jpg, .png, etc.)
3. Парсинг пути: Имя_Сотрудника/ГГГГММДД/ЧЧММСС.jpeg
4. Регистрация сотрудника в БД (если новый)
5. Копирование файла в структурированное хранилище
6. Запись метаданных в таблицу screenshots (status='pending')
7. Удаление исходного файла
```

**Особенности:**
- Рекурсивное сканирование директорий
- Валидация формата имен файлов
- Избежание дубликатов (проверка существования)
- Логирование всех операций
- Graceful shutdown при KeyboardInterrupt

### 2. OCR Analyzer (Модуль анализа)

**Ответственность:** Распознавание текста и классификация активности

**Технологии:**
- Python 3.11
- Tesseract OCR 5.x (с русским языковым пакетом)
- pytesseract (Python обертка)
- Pillow (предобработка изображений)

**Основные компоненты:**
- `analyzer.py` - Главный цикл обработки
- `ocr_engine.py` - Обертка для Tesseract
- `keyword_classifier.py` - Классификатор по ключевым словам
- `database.py` - Расширенный DB менеджер с методами для UI

**Алгоритм работы:**
```
1. Запрос скриншотов со статусом 'pending' (батч по 10)
2. Для каждого скриншота:
   a. Предобработка изображения (grayscale, contrast, scale 2x)
   b. OCR распознавание (rus+eng, PSM 6)
   c. Загрузка словарей из БД
   d. Поиск ключевых слов в тексте
   e. Расчет уверенности классификации
   f. Сохранение результата в analysis_results
   g. Обновление статуса скриншота на 'analyzed'
3. Ожидание 60 секунд и повтор
```

**Предобработка изображений:**
1. Конвертация в grayscale (L mode)
2. Увеличение контраста (enhance 2.0x)
3. Масштабирование 2x (LANCZOS resampling)

**Классификация:**
```python
prod_count = количество продуктивных слов в тексте
unprod_count = количество непродуктивных слов в тексте

if prod_count > unprod_count:
    category = 'productive'
    confidence = prod_count / (prod_count + unprod_count)
elif unprod_count > prod_count:
    category = 'unproductive'
    confidence = unprod_count / (prod_count + unprod_count)
else:
    category = 'unknown'
    confidence = 0.5
```

**Оптимизации:**
- Батчевая обработка (10 скриншотов за раз)
- Кэширование словарей в памяти
- Асинхронность через time.sleep()
- Ограничение ресурсов Docker (2 CPU, 2GB RAM)

### 3. Dashboard (Веб-интерфейс)

**Ответственность:** Визуализация данных и управление системой

**Технологии:**
- Streamlit 1.30.0
- Plotly 5.18.0 (графики)
- Pandas 2.1.4 (таблицы)

**Страницы:**

#### 0_📊_Главная.py
- KPI карточки (всего/продуктивных/непродуктивных/%)
- Линейный график продуктивности по дням
- Таблица рейтинга сотрудников с прогресс-барами
- Фильтры по датам

#### 1_👤_Профиль_сотрудника.py
- Выпадающий список сотрудников
- Выбор даты
- Статистика за день (метрики)
- Лента скриншотов с цветовой маркировкой:
  - 🟢 Продуктивно
  - 🔴 Непродуктивно
  - ⚪ Не определено
- Просмотр изображений и распознанного текста

#### 2_🚨_Лента_нарушений.py
- Фильтр по периоду
- Только непродуктивные скриншоты
- Информация о сотруднике, времени, уверенности
- Быстрый просмотр изображений и OCR текста

#### 3_📚_Управление_словарем.py
- Два таба (продуктивные/непродуктивные)
- CRUD операции с ключевыми словами
- Загрузка стандартного словаря
- Мгновенное применение изменений

**Авторизация:**
- Хеширование паролей SHA256 + соль
- Session state для отслеживания входа
- Защита всех страниц через require_auth()
- Кнопка выхода в sidebar

**База данных (общая для всех модулей):**

```sql
employees
├── id (PK)
├── name (UNIQUE)
└── created_at

screenshots
├── id (PK)
├── employee_id (FK → employees)
├── file_path
├── capture_time
├── capture_date
├── status (pending/analyzed/error)
└── created_at

analysis_results
├── id (PK)
├── screenshot_id (FK → screenshots, UNIQUE)
├── ocr_text
├── category (productive/unproductive/unknown)
├── confidence (0.0-1.0)
└── analyzed_at

keywords
├── id (PK)
├── word (UNIQUE)
├── category (productive/unproductive)
├── created_at
└── created_by (system/admin)
```

**Индексы:**
- `idx_screenshots_date` - для фильтрации по датам
- `idx_screenshots_employee` - для профилей сотрудников
- `idx_analysis_category` - для ленты нарушений
- `idx_keywords_category` - для загрузки словарей

## Инфраструктура

### Docker Compose

**Сервисы:**

1. **data-collector**
   - Build: ./data-collector
   - Volumes: storage, db-init, incoming (read-only)
   - Environment: пути, интервал сканирования
   - Restart: unless-stopped

2. **ocr-analyzer**
   - Build: ./ocr-analyzer (с Tesseract)
   - Volumes: storage, db-init
   - Resources: 2 CPU, 2GB RAM
   - Environment: языки OCR, размер батча

3. **dashboard**
   - Build: ./dashboard
   - Ports: 8501:8501
   - Volumes: storage, db-init
   - Depends on: data-collector, ocr-analyzer
   - Environment: credentials, salt

**Сеть:**
- Custom bridge network: analytics-network
- Изоляция от внешних сетей
- Internal DNS resolution

**Volumes:**
- ./storage - общие данные (скриншоты, БД, логи)
- ./db-init - SQL схема (read-only)
- ./incoming - входящие файлы (read-only)

## Поток данных

```
1. Сотрудник делает скриншот
   ↓
2. Скриншот сохраняется в D:/Скрин/Имя/Дата/Время.jpeg
   ↓
3. Data Collector (каждые 5 мин):
   - Сканирует папку
   - Копирует в storage/screenshots/YYYY-MM-DD/Имя/
   - Записывает в БД (status='pending')
   - Удаляет оригинал
   ↓
4. OCR Analyzer (каждые 60 сек):
   - Берет скриншоты со status='pending'
   - Распознает текст (Tesseract)
   - Классифицирует (keyword matching)
   - Сохраняет результат
   - Обновляет status='analyzed'
   ↓
5. Dashboard (on-demand):
   - Читает данные из БД
   - Визуализирует статистику
   - Показывает изображения
   - Позволяет управлять словарем
```

## Безопасность

### Уровень 1: Авторизация
- SHA256 хеширование паролей
- Соль для защиты от rainbow tables
- Session-based authentication

### Уровень 2: Доступ к данным
- Read-only монтирование входящих файлов
- Нет прямого доступа к файловой системе хоста
- Изоляция контейнеров в собственной сети

### Уровень 3: Хранение
- Локальное хранение (нет облака)
- Возможность шифрования диска (BitLocker)
- Регулярные бэкапы БД

### Рекомендации:
- Изменить пароль по умолчанию
- Настроить firewall для порта 8501
- Использовать VPN для удаленного доступа
- Включить аудит логов

## Масштабируемость

### Вертикальное масштабирование (текущая архитектура):
- Увеличить CPU/RAM для OCR контейнера
- Уменьшить PROCESSING_INTERVAL
- Увеличить BATCH_SIZE

### Горизонтальное масштабирование (будущее):
- Переход на PostgreSQL
- Очередь задач (Redis + Celery)
- Несколько worker контейнеров для OCR
- Load balancer для dashboard

### Ограничения текущей версии:
- SQLite: ограничение на concurrent writes
- Single-threaded OCR processing
- No distributed caching

## Отказоустойчивость

### Обработка ошибок:

**Data Collector:**
- Пропуск файлов с неверным форматом
- Продолжение при ошибке копирования
- Логирование и переход к следующему файлу

**OCR Analyzer:**
- Пропуск отсутствующих файлов
- Возврат пустого текста при ошибке OCR
- Обновление status='error' для проблемных файлов
- Graceful degradation при отсутствии словарей

**Dashboard:**
- Проверка существования файлов перед загрузкой
- Fallback при ошибках БД
- Информативные сообщения пользователю

### Recovery:
- Restart policy: unless-stopped
- Автостарт после перезагрузки сервера
- Сохранение состояния в БД (можно продолжить после сбоя)
